# BUG-002 — Mover restores department access for Terminated employees

- **Severity:** Critical
- **Priority:** High
- **Requirement:** REQ-011 (Access Revocation) — primary, the
  guarantee that revoked access does not return. Related: REQ-008
  (Mover department reconciliation), whose logic is what causes this.
- **Environment:** Keycloak 26.7.3 (Docker), `update-users.ps1`,
  executed via `acme-provisioner`.

## Preconditions

An employee (`E004`, Eleni) was `Terminated` and fully processed by
`deprovision-users.ps1` earlier: account disabled, `department-sales`
and `employee` role removed. `E004` remains present in
`data/employees.csv` with `Status=Terminated`, but `Department=Sales`
and `Role=Employee` unchanged from before termination.

## Steps to Reproduce

1. Ensure an employee has been `Terminated` and processed by
   `deprovision-users.ps1` (groups/roles removed, account disabled).
2. Run `.\scripts\update-users.ps1`, with no other CSV change (the
   employee's `Department`/`Role` fields still reflect their
   pre-termination values, only `Status` differs).

## Expected Result

The Mover must not restore group or role access for a `Terminated`
employee — revoked access must not return, regardless of what the
`Department`/`Role` fields say.

## Actual Result

The Mover detects `current: []` vs `desired: department-sales` for
`E004` and adds the department group back — restoring department-level
access despite the employee being `Terminated` and disabled.

```
E004: department change detected - current: [], desired: department-sales
E004: moved to department-sales
E004: role already correct (employee)
```

Actual Keycloak state after this execution:
```
Enabled: false
Groups: department-sales
Roles: default-roles-acme  (no "employee" — see BUG-003)
```

## Root Cause / Suspected Cause

`update-users.ps1` performs Department/Role reconciliation without
checking the employee's lifecycle `Status` — it treats every CSV row
as if the employee were active, regardless of `Terminated`.

## Impact

A terminated identity can regain department-level group membership
if the Mover runs after the Leaver (or independently, on any
schedule) — a real security exposure, since group membership could be
consulted by other systems/checks even while the account itself is
disabled. This directly violates REQ-011's revocation guarantee.
